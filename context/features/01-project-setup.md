# Stage 01 – Project Setup

## Goal
Bootstrap a working Next.js application with the correct tooling, folder structure, and base UI shell that all subsequent stages will build on.

## Deliverables

### 1. Next.js App
- Create a new Next.js app using the App Router (`app/` directory)
- TypeScript enabled
- Tailwind CSS configured
- ShadCN UI initialized (`npx shadcn@latest init`) — use the default style, CSS variables enabled
  - Install baseline components needed from the start: `button`, `card`, `badge`, `skeleton`, `input`, `select`, `separator`, `tooltip`

### 2. Folder Structure
```
app/
  layout.tsx          # Root layout with fonts, global styles
  page.tsx            # Landing / marketing page (placeholder)
  (auth)/             # Route group for auth pages
  (app)/              # Route group for protected app pages
components/
  ui/                 # ShadCN generated components (do not hand-edit)
lib/                  # Utility functions and shared logic
```

### 3. Base Layout
- Root layout includes: HTML shell, font setup (e.g. Inter via `next/font`), global Tailwind styles
- A simple top-level navigation bar component (logo + placeholder nav links)
- Dark/light-mode friendly colour tokens via Tailwind config

### 4. Landing Page (placeholder)
- Headline: "FlowState – Understand your deep work"
- Subheading describing the product in one sentence
- "Get Started" CTA button (links to `/sign-in`, not yet functional)

### 5. Environment File
- `.env.local.example` listing all env vars that will be required throughout the project (empty values)

## Acceptance Criteria
- `npm run dev` starts the app with no errors
- Landing page renders at `http://localhost:3000`
- Tailwind utility classes work
- ShadCN `Button` and `Card` components render correctly on the landing page
- TypeScript compiles with no errors (`npm run build`)

## Git Workflow Convention
All branch operations throughout the project use `git switch`:
- Create and switch to a new branch: `git switch -c feature/my-feature`
- Switch to an existing branch: `git switch main`
- Never use `git checkout` for branch switching

## Notes
- Do not add any auth, database, or API logic in this stage
- Keep the landing page minimal — it will not be revisited until the polish stage
- ShadCN components live in `components/ui/` and are generated by the CLI — do not hand-edit them; extend via wrapper components instead
